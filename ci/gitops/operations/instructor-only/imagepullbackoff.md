2. Review a request in `operations/requests.json` for Dev operation `fixture-t3-cycle`: `source_sha` (immutable reviewed commit), `expires_at` (UTC ISO timestamp), `change_request`, `data_decision`, and `hold_seconds` (30–900). Preprovisioned scoped Namespace `incident-fixture-t3` must match protected `fixture_namespace_uids[case]` and the installer label `platform.course/fixture-namespace`. The five fixed fixture object names must be absent. No runtime shell or target input is accepted.
3. Dispatch that fixed operation on main. Review the exact private action/UID plan in the protected mutate Environment. The access installer preprovisions the dedicated namespace and RoleBindings. CI creates only the quota, tokenless ServiceAccount, probe ConfigMap, restrictive NetworkPolicy and one Deployment. A healthy baseline is required before injection.
4. Positively verify an absent immutable ECR digest, then replace only the fixture container image. CI records `ImagePullBackOff` from Pods owned by the captured Deployment UID, then restores the exact original Pod template in `finally`. Missing evidence fails the exercise instead of fabricating success. Healthy rollout and original UID must verify before the incident marker becomes idle.
5. If cancellation/recovery fails, dispatch `fixture-t3-restore` against the captured marker; other cloud operations remain paused. For cleanup, dispatch `fixture-t3-cleanup` with its creation receipt descriptor (`key`, `version`, `sha256`) or matching unresolved marker. Cleanup deletes only the five acknowledged object UIDs, refuses changed/replaced targets and retains the namespace/RoleBindings. It never inventories unrelated Secrets or removes finalizers forcibly.
